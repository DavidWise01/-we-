# WAG-223 — Packet integrity, authorization, and claimed ancestry
.dlw

The lab implements SHA-256 and HMAC-SHA256, checks their published known-answer vectors, hashes deterministic ASCII JSON payloads, authenticates packets under a fixture trust registry, enforces epoch 5, and checks claimed acquisition roots. It is important to separate (1) packet unchanged (digest), (2) fixture key holder authorized (HMAC), and (3) acquisition history truthful (NOT proven). HMAC is a symmetric message authentication code, not a digital signature.

Tested 320 pairs: ten scenario families by four periods by eight fixed seeds. 2 known-answer cryptographic checks passed. The simulated malicious authorized-collusion condition produced 32 false independent agreements despite valid packet authentication and distinct claimed roots. Further tests include stale packets, unauthorized identifiers, absent packet, modified events, modified root, corrupt MAC and unknown provenance. Each is preserved in evidence.json.

All fixture keys appear directly in public JS. This is **not** secure production key storage, real external witness authentication, trusted time, hardware attestation, or a guarantee of genuinely independent acquisition. Repeated seeded cases may be exact duplicates, not independent replications. Canonical JSON here is a fixed local object serializer, not general RFC canonical JSON across environments.
